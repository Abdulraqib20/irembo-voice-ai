\section*{Approach}
I fine-tuned a multilingual transformer, Davlan/afro-xlmr-base, for intent classification. This model was selected because it includes African language coverage and handles morphology and code-switching between Kinyarwanda and English. A rule-based classifier provides a fast baseline and optional fallback. The transformer is the primary model because it delivers higher macro performance across all intents.

\paragraph{Why this fits Voice AI}
The system must work on noisy ASR outputs and handle mixed-language utterances. The transformer model captures semantic variations, paraphrases, and informal phrasing better than keyword rules, while the rule-based baseline offers low latency and interpretable failure modes.

\section*{Data Strategy}
The dataset uses three splits: 561 train, 70 validation, and 69 test samples. Preprocessing standardizes fields and produces a HuggingFace JSON format for training and evaluation.

\paragraph{Noise and transcription errors}
We retain noise to reflect real ASR conditions. Basic normalization is limited to whitespace handling to avoid destroying code-switched tokens. Future work can include ASR confidence-based filtering and spelling normalization.

\paragraph{Code-switching}
Training includes Kinyarwanda, English, and mixed utterances. The tokenizer learns cross-language subwords. Evaluation is reported per language to ensure mixed and Kinyarwanda performance remain strong.

\paragraph{Low-resource strategy}
We used the provided labeled data for core training. To mitigate low-resource constraints, we propose augmentation such as template-based paraphrasing and back-translation for Kinyarwanda and mixed examples. These are documented as future improvements rather than applied changes.

\section*{Evaluation}
We report accuracy, macro precision, macro recall, and macro F1. Macro metrics are chosen to weight all intents equally, which is critical for public services. Weighted metrics can hide poor performance on rare intents.

\paragraph{Per-language accuracy}
English 90.5\%, code-switched 100.0\%, Kinyarwanda 97.4\%. This demonstrates strong performance on the target language and on mixed utterances.

\paragraph{Robustness and failure modes}
We inspect per-intent metrics in the evaluation scripts and recommend a confusion matrix to identify ambiguous intent pairs such as requirements information versus fees information. These analyses guide dataset expansion and intent definition refinement.

\section*{MLOps and Production Considerations}

\subsection*{Model Versioning and Deployment Strategy}

I implemented a file-based model registry (\texttt{src/config/model\_registry.py}) that tracks:
\begin{itemize}
  \item Model versions with semantic versioning (v1.0.0, v1.1.0, etc.)
  \item Training configuration and hyperparameters
  \item Evaluation metrics at registration time
  \item Data hash for reproducibility verification
  \item Active version tracking with rollback capability
\end{itemize}

For deployment, the system uses a FastAPI inference API (\texttt{src/api/inference\_api.py}) with:
\begin{itemize}
  \item Model loading at startup with device detection (CPU/GPU)
  \item Health and readiness endpoints for Kubernetes orchestration
  \item Single-request and batch classification endpoints
  \item Three-tier confidence-based fallback: Transformer $\rightarrow$ Rule-based $\rightarrow$ Groq LLM
\end{itemize}

\subsection*{Monitoring in Production}

The monitoring module (\texttt{src/config/monitoring.py}) provides real-time observability:
\begin{itemize}
  \item \textbf{Latency tracking:} Average and P95 latency per request window
  \item \textbf{Confidence monitoring:} Tracks average confidence and low-confidence rate (requests below threshold)
  \item \textbf{Fallback rate:} Percentage of requests routed to fallback systems
  \item \textbf{Distribution drift detection:} Compares current language distribution against training baseline, alerts on significant shifts (>15\%)
  \item \textbf{Per-request logging:} JSONL logs with request ID, utterance, intent, confidence, latency for offline analysis
\end{itemize}

Alerts trigger when: low-confidence rate exceeds 20\%, fallback rate exceeds 15\%, P95 latency exceeds 300ms, or language distribution drifts more than 15\% from baseline.

\subsection*{Real-Time Voice AI Pipeline Integration}

The classifier integrates into a Voice AI pipeline as follows:

\begin{enumerate}
  \item \textbf{ASR Output:} Speech-to-text provides transcribed utterance
  \item \textbf{Language Detection:} Enhanced detector identifies en/rw/mixed
  \item \textbf{Intent Classification:} Transformer model predicts intent with confidence
  \item \textbf{Confidence Check:} If below 0.7 threshold, route to fallback
  \item \textbf{Action Dispatch:} Map intent to backend service (status check, booking, etc.)
\end{enumerate}

The API exposes \texttt{/classify} for real-time single requests (target latency under 100ms on GPU) and \texttt{/classify/batch} for offline bulk processing.

\subsection*{Fallback Strategies for Low-Confidence Predictions}

The system implements a three-tier fallback strategy:
\begin{enumerate}
  \item \textbf{Tier 1 (Primary):} Transformer model with 0.7 confidence threshold
  \item \textbf{Tier 2 (Secondary):} If confidence is low, compare with rule-based classifier; use whichever has higher confidence
  \item \textbf{Tier 3 (Tertiary):} If both have low confidence, use Groq LLM API as last resort
  \item \textbf{Logging:} All fallback events logged with reason for post-hoc analysis
\end{enumerate}

This tiered approach protects citizens from incorrect service routing while maintaining high availability and leveraging the strengths of each classifier (speed, interpretability, and semantic understanding).

\section*{Ethics and Public Sector Considerations}
Government services require fairness and transparency. We prioritize macro F1 performance to avoid neglecting rare intents that may affect specific citizen groups. We recommend regular audits for language and demographic bias. The system provides clear confidence signals when escalating to human agents, ensuring citizens understand when the AI cannot assist. Explanations should be available at the intent level, showing relevant keywords or example utterances used in classification.

\section*{Tradeoffs and Limitations}

The transformer offers higher accuracy (95.65\%) but higher per-request latency ($\sim$750ms including Groq) compared to rule-based systems (16ms). The dataset is small (700 samples), so results should be validated with additional real-world utterances before production deployment. Augmentation and active learning are recommended to expand coverage, especially for underrepresented intents. The three-tier fallback with Groq LLM adds external API dependency and cost considerations for large-scale deployments.

\section*{Conclusion}

AfroXLMR base provides a reliable, multilingual intent classifier for the Irembo Voice AI use case. It performs strongly on Kinyarwanda (97.4\%) and code-switched speech (100\%) and integrates seamlessly into a production pipeline with confidence-based fallbacks (rule-based + Groq LLM) and comprehensive monitoring. The system is designed to be fair (macro F1 metrics), transparent (logging all decisions), and resilient (three-tier fallback) for a citizen-facing government services platform.
